# EPCOT Explore Map — artwork provenance and rights

## What this is

EPCOT's Explore Map has **no raster image asset at all** — no `epcot_map`
imageset, nothing cropped or traced from any outside source, nothing
generated by an image model. It is rendered entirely as vector SwiftUI
drawing from two pre-existing, hand-authored Swift data files:

- `Parkio/Features/Map/Models/ParkCompositions.swift` → `EPCOTComposition` —
  authored polygon/ellipse/rect shapes (lagoon, land masses, promenade ring,
  Spaceship Earth landmark) in a normalized 0–1 coordinate space, drawn by
  `CompositionMapCanvas` (`ParkMapBackgroundView.swift`).
- `Parkio/Features/Map/Views/ParkMapBackgroundView.swift` → `ParkLayout.epcot`
  — authored named-zone labels and SF Symbol icons ("World Discovery" + atom,
  "World Nature" + leaf, "World Showcase" + globe, etc.), drawn by `ZoneView`.

Both files already existed in the repository before this task, written as
part of the general six-park composition/placeholder system. This task's
only change to them was *activating* a rendering path that was previously
dead code (`ZoneView`'s labels were never actually layered onto
`CompositionMapCanvas`, and nothing routed EPCOT to the canvas renderer at
all) — no new shapes, zones, or compositional layout were authored for this
task, and nothing was copied, traced, or cropped from any Disney map, guide,
or photograph at any point, past or present.

## Why this satisfies "original illustration, not reproduced Disney artwork"

Per the explicit decision behind this task (*"We want original Parkio
illustrated maps... We will not copy additional official Disney map
artwork"*), raster map art was deliberately **not** created for this pass —
there is no new image file to evaluate for licensing risk, unlike
[`magic_kingdom_map`](MK-MAP-PROVENANCE.md), which is a crop of Disney's own
official guest guide map with no documented rights (see that file's own
provenance notes). EPCOT's Explore Map has no equivalent raster source,
official or otherwise, to be concerned about: it is code that draws shapes
and SF Symbols, the same way a chart-drawing library renders a bar chart.

The land names used as zone labels ("World Celebration", "World Discovery",
"World Nature", "World Showcase") and the general fact that World Showcase
pavilions ring a central lagoon are generic, non-expressive facts about the
park's real-world layout — not copyrightable creative expression, and not
sourced from any single Disney document. Attraction and dining names
(e.g. "Spaceship Earth", "Soarin'", "Akershus Royal Banquet Hall") are
factual identifiers already used throughout the rest of this app (menus,
search, wait times) under the same reasoning Magic Kingdom's existing pin
labels already rely on.

## What would need new provenance review

If a future pass replaces this vector rendering with actual commissioned or
generated illustration (raster art, in the way `magic_kingdom_map` is),
*that* asset would need its own provenance file following this same
structure, documenting who created it and under what terms — exactly the gap
this file is written to avoid repeating.

## Pin calibration

`ParkMapPinData.epcotPins` (`Parkio/Features/Map/Models/ParkMapPinData.swift`)
is calibrated against this composition's authored zone layout — a "starter
calibration" in the same sense every non-Magic-Kingdom park's pins in that
file already are (per that file's own header comment), not pixel-matched
against a photographed map the way Magic Kingdom's are against its real
artwork. World Showcase dining pins are arranged in real-world clockwise
pavilion order (Mexico → Norway → China → Germany → Italy → America → Japan
→ Morocco → France → United Kingdom → Canada) along the composition's south
arc, evenly spaced, with each pavilion's venues clustered around its anchor
point. Positions can be refined in-app later via `CalibrationViewModel`
(drag-to-adjust, exports ready-to-paste Swift literals) without needing a
reference image to drag against, since the canvas itself — the authored
composition — is the reference.
